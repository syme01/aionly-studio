## 1. 项目打包概述

### 1.1 打包流程

```
源代码 (src/)
    ↓
编译构建 (pnpm build)
    ↓
生成 out/ 目录
    ├── main/         # 主进程编译后代码
    ├── renderer/     # 渲染进程静态文件
    └── preload/      # 预加载脚本
    ↓
electron-builder 打包
    ↓
打包 out/ + node_modules + resources
    ↓
生成安装包
    ├── Windows: .exe (NSIS) / .exe (Portable)
    ├── macOS: .dmg / .zip
    └── Linux: .AppImage / .deb / .rpm
```

### 1.2 关键配置文件

| 文件 | 作用 |
|------|------|
| `package.json` | 项目元信息、依赖、构建脚本 |
| `electron-builder.yml` | 打包配置、发布配置 |
| `electron.vite.config.ts` | Vite 构建配置 |
| `app-upgrade-config.json` | 应用更新配置 |

## 2. 打包命令

### 2.1 完整构建命令

```bash
# 1. 安装依赖
pnpm install

# 2. 构建代码（生成 out/ 目录）
pnpm build

# 3. 打包安装程序
pnpm build:win      # Windows (x64 + arm64)
pnpm build:mac      # macOS (Intel + Apple Silicon)
pnpm build:linux    # Linux (x64 + arm64)
```

### 2.2 单平台打包

```bash
# Windows
pnpm build:win:x64      # 仅 x64
pnpm build:win:arm64    # 仅 ARM64

# macOS
pnpm build:mac:x64      # 仅 Intel
pnpm build:mac:arm64    # 仅 Apple Silicon

# Linux
pnpm build:linux:x64    # 仅 x64
pnpm build:linux:arm64  # 仅 ARM64
```

### 2.3 测试打包（不压缩）

```bash
pnpm build:unpack
# 输出到 dist/[platform]-unpacked/
```

## 4. 页面加载机制

### 4.1 开发环境 vs 生产环境

应用窗口加载页面的方式根据运行环境不同：

| 环境 | 加载方式 | 地址示例 |
|------|---------|----------|
| **开发环境** | `loadURL()` - 网络地址 | `http://localhost:5173` |
| **生产环境** | `loadFile()` - 本地文件 | `file:///path/to/out/renderer/index.html` |

### 4.2 代码实现

**位置**: `src/main/services/WindowService.ts:360-365`

```typescript
private loadMainWindowContent(mainWindow: BrowserWindow) {
  if (is.dev && process.env['ELECTRON_RENDERER_URL']) {
    // 开发环境：加载 Vite dev server
    void mainWindow.loadURL(process.env['ELECTRON_RENDERER_URL'])
  } else {
    // 生产环境：加载打包后的本地文件
    void mainWindow.loadFile(join(__dirname, '../renderer/index.html'))
  }
}
```

### 4.3 多窗口支持

应用支持多个窗口，每个窗口对应不同的 HTML 入口：

```typescript
// 主窗口
mainWindow.loadFile('out/renderer/index.html')

// 迷你窗口
miniWindow.loadFile('out/renderer/miniWindow.html')

// 选择工具栏窗口
toolbarWindow.loadFile('out/renderer/selectionToolbar.html')

// 追踪窗口
traceWindow.loadFile('out/renderer/traceWindow.html')
```

### 4.4 重要说明

✅ **打包后的应用完全使用本地文件**
- 所有页面通过 `file://` 协议加载
- 不需要网络连接即可运行
- `out/renderer/` 目录已被打包到安装包中

❌ **不需要单独部署 out/ 文件夹**
- electron-builder 已自动打包 `out/` 目录
- 用户只需安装 `.exe`/`.dmg`/`.AppImage` 等安装包

## 5. 部署清单

### 5.1 用户端部署

**用户只需要下载并安装对应平台的安装包：**

| 平台 | 文件名 | 说明 |
|------|--------|------|
| Windows 安装版 | `AiOnly-1.9.9-x64-setup.exe` | NSIS 安装程序，推荐 |
| Windows 便携版 | `AiOnly-1.9.9-x64-portable.exe` | 无需安装，解压即用 |
| macOS Apple Silicon | `AiOnly-1.9.9-arm64.dmg` | M1/M2/M3 芯片 |
| macOS Intel | `AiOnly-1.9.9-x64.dmg` | Intel 芯片 |
| Linux AppImage | `AiOnly-1.9.9-x64.AppImage` | 通用格式 |
| Linux Debian/Ubuntu | `AiOnly-1.9.9-x64.deb` | apt 包管理器 |
| Linux RedHat/Fedora | `AiOnly-1.9.9-x64.rpm` | yum/dnf 包管理器 |

### 5.2 安装包内容

每个安装包已包含以下内容，**无需额外部署任何文件**：

```
安装包内容：
├── Electron 运行时
├── Node.js 运行时
├── out/                    # 编译后的应用代码
│   ├── main/              # 主进程
│   ├── renderer/          # 渲染进程（HTML/CSS/JS）
│   └── preload/           # 预加载脚本
├── node_modules/          # 生产依赖（已过滤开发依赖）
├── resources/             # 运行时资源
│   └── database/          # 数据库迁移文件
└── 应用图标、元数据等
```

### 5.3 特殊处理文件

以下文件**不会**被打包到 asar 档案中（`electron-builder.yml:72-76`）：

```yaml
asarUnpack:
  - out/proxy/**                    # 代理相关代码
  - resources/**                    # 资源文件
  - "**/*.{metal,exp,lib}"         # 原生库文件
  - "node_modules/@img/sharp-*/**" # 图片处理库
```

这些文件需要以原始形式存在，以便运行时动态加载。

## 6. 更新服务器配置

### 6.1 配置更新服务器地址

有两种方式修改更新服务器地址：

#### 方式一：修改 electron-builder.yml（推荐）

**文件位置**: `electron-builder.yml:133-135`

```yaml
publish:
  provider: generic
  url: https://your-server.com  # 改为你的服务器地址
```

#### 方式二：修改常量文件

**文件位置**: `packages/shared/config/constant.ts`

```typescript
export enum FeedUrl {
  PRODUCTION = 'https://your-server.com',  // 改为你的服务器地址
  GITHUB_LATEST = 'https://gitee.com/myme/aionly-studio/releases/latest/download'
}
```

### 6.2 更新服务器文件结构

你的更新服务器需要提供以下文件：

```
https://your-server.com/
├── latest.yml                              # Windows 更新元数据
├── latest-mac.yml                          # macOS 更新元数据
├── latest-linux.yml                        # Linux 更新元数据
├── AiOnly-1.9.9-x64-setup.exe       # Windows 安装包
├── AiOnly-1.9.9-x64-portable.exe    # Windows 便携版
├── AiOnly-1.9.9-arm64.dmg           # macOS Apple Silicon
├── AiOnly-1.9.9-x64.dmg             # macOS Intel
├── AiOnly-1.9.9-x64.AppImage        # Linux AppImage
├── AiOnly-1.9.9-x64.deb             # Linux deb
└── AiOnly-1.9.9-x64.rpm             # Linux rpm
```

### 6.3 元数据文件格式

#### latest.yml 示例（Windows）

```yaml
version: 1.9.9
releaseDate: '2026-06-09T00:00:00.000Z'
path: AiOnly-1.9.9-x64-setup.exe
sha512: YourSHA512HashHere==
releaseNotes: |
  ## 版本 1.9.9 更新内容
  
  ### 新增功能
  - 新增功能1说明
  - 新增功能2说明
  
  ### 问题修复
  - 修复问题1
  - 修复问题2
```

#### latest-mac.yml 示例（macOS）

```yaml
version: 1.9.9
releaseDate: '2026-06-09T00:00:00.000Z'
path: AiOnly-1.9.9-arm64.dmg
sha512: YourSHA512HashHere==
releaseNotes: |
  ## Version 1.9.9
  
  ### New Features
  - Feature 1
  - Feature 2
  
  ### Bug Fixes
  - Fix 1
  - Fix 2
```

### 6.4 多语言更新说明

支持在 `releaseNotes` 中使用多语言标记：

```yaml
releaseNotes: |
  <!--LANG:en-->
  ## Version 1.9.9
  
  ### New Features
  - Feature 1
  
  <!--LANG:zh-CN-->
  ## 版本 1.9.9
  
  ### 新增功能
  - 功能1
  
  <!--LANG:END-->
```

客户端会根据用户语言自动提取对应语言的内容。

### 6.5 生成 SHA512 哈希

安装包的 SHA512 哈希用于验证文件完整性：

```bash
# macOS/Linux
shasum -a 512 "AiOnly-1.9.9-x64-setup.exe" | awk '{print $1}' | base64

# Windows PowerShell
certUtil -hashfile "AiOnly-1.9.9-x64-setup.exe" SHA512
# 然后将输出转换为 base64 格式
```

### 6.6 自动更新流程

```
用户启动应用
    ↓
检查更新 (AppUpdater.ts)
    ↓
请求更新服务器 (latest.yml)
    ↓
比对版本号
    ↓
版本更新可用？
    ├─ 是 → 下载安装包
    │         ↓
    │    显示更新弹窗 (UpdateDialogPopup.tsx)
    │         ↓
    │    用户选择：立即安装 / 稍后 / 忽略
    │         ↓
    │    安装并重启
    │
    └─ 否 → 继续使用当前版本
```


#### package.json

```json
{
  "name": "YourApp",
  "version": "1.0.0",
  "description": "Your app description",
  "author": "your-email@example.com",
  "homepage": "https://your-website.com"

```

### 7.2 应用标识说明

| 字段 | 说明 | 示例 |
|------|------|------|
| `appId` | 应用唯一标识，用于系统识别 | `com.company.appname` |

| `version` | 应用版本号（语义化版本） | `1.0.0` |

替换以下文件：

```
build/
├── icon.png              # 通用图标 (512x512)
├── icon.ico              # Windows 图标
├── icon.icns             # macOS 图标
└── tray_icon.png         # 系统托盘图标
```

### 7.4 代码签名配置（可选）

#### Windows 代码签名

```yaml

  signtoolOptions:
    sign: scripts/win-sign.js  # 自定义签名脚本
  certificateFile: path/to/cert.pfx
```


## 8. 常见问题

### 8.1 打包失败

**问题**: 执行 `pnpm build:win` 时报错

**可能原因**:
- Node.js 版本不符合要求（需要 ≥24.11.1）
- 缺少依赖包
- 磁盘空间不足

**解决方法**:
```bash
# 1. 检查 Node.js 版本
node -v

# 2. 清理并重新安装依赖
rm -rf node_modules pnpm-lock.yaml
pnpm install

# 3. 清理构建缓存
rm -rf out dist

# 4. 重新构建
pnpm build
pnpm build:win
```

### 8.2 打包后安装包无法运行

**问题**: 安装后双击无反应或闪退

**可能原因**:
- 缺少必要的系统依赖（Linux）
- 代码签名问题（macOS/Windows）
- 安装包损坏

**解决方法**:
```bash
# Linux: 安装依赖
sudo apt-get install libgtk-3-0 libnotify4 libnss3 libxss1

# macOS: 允许未签名应用
xattr -cr "/Applications/AiOnly.app"

# Windows: 检查日志
# 查看 %APPDATA%/AiOnly/logs/ 目录
```

### 8.3 更新检查失败

**问题**: 应用内点击"检查更新"无响应

**可能原因**:
- 更新服务器地址配置错误
- 网络连接问题
- 元数据文件格式错误

**解决方法**:
1. 检查 `electron-builder.yml` 中的 `publish.url` 配置
2. 确认服务器上存在 `latest.yml` 文件
3. 验证元数据文件格式是否正确
4. 查看日志: `AppData/AiOnly/logs/`

### 8.4 打包体积过大

**问题**: 生成的安装包超过 500MB

**可能原因**:
- 包含了开发依赖
- 包含了不必要的文件
- node_modules 未清理

**解决方法**:

检查 `electron-builder.yml` 中的文件过滤规则（第20-76行）：

```yaml
files:
  - "**/*"
  - "!src"              # 排除源代码
  - "!tests"            # 排除测试文件
  - "!**/*.{map,ts}"   # 排除 source map 和 TS 文件
```

### 8.5 out 目录不存在

**问题**: 执行 `pnpm build:win` 时提示找不到 out 目录

**原因**: 没有先执行 `pnpm build` 生成编译产物

**解决方法**:
```bash
# 正确的打包流程
pnpm build        # 先编译，生成 out/
pnpm build:win    # 再打包
```

### 8.6 Windows Defender 误报

**问题**: Windows 提示应用为病毒

**原因**: 未签名的 Electron 应用容易被误报

**解决方法**:
1. 申请 Windows 代码签名证书
2. 配置代码签名（见 7.4 节）
3. 提交白名单申请给微软

### 8.7 macOS 提示"已损坏"

**问题**: macOS 提示"应用已损坏，无法打开"

**原因**: 应用未签名或未公证

**解决方法**:
```bash
# 临时解决：移除隔离属性
xattr -cr "/Applications/AiOnly.app"

# 永久解决：配置代码签名和公证（见 7.4 节）
```
